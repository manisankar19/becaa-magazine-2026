# Sprint v3 — Threat checks (PRD §5.7)

Each row of the PRD threat table with the automated test that exercises it, or the manual check performed. Test names are files under `05_WEBSITE/tests/`; run `npm run test:unit && npm run test:integration` (local PostgreSQL required) and the E2E suites listed.

| Threat | Control | Verification |
|---|---|---|
| SQL injection | Parameterised queries only; no string-built SQL | `integration/admin-queries.test.mjs` (`' OR 1=1 --` and `%` as search text), `integration/threats.test.mjs` (`npm run check:sql` passes on the tree and fails on a template-literal fixture), `unit/check-sql-core.test.mjs` |
| XSS (stored, via names/organisation shown in admin) | All output inserted with `textContent`; strict CSP `default-src 'self'`; JSON responses with `nosniff` | `e2e/admin-page.test.mjs` (`<script>`/`<img onerror>` payloads render as text, zero `script`/`img` nodes, no CSP violations), `integration/threats.test.mjs` (API returns JSON only) |
| CSRF on admin POST/DELETE and register | `SameSite` cookies, `Origin`/`Referer` check, synchroniser token bound to the admin session | `integration/register.test.mjs` (foreign/missing Origin → 403), `integration/admin-auth.test.mjs` (logout without token / foreign origin → 403), `integration/admin-queries.test.mjs` (delete without token / foreign origin → 403), `integration/threats.test.mjs` (foreign Referer → 403; cross-site export unauthenticated) |
| Brute force / credential stuffing | Per-IP rate limit, per-username lockout, argon2id, constant-time compare | `integration/admin-auth.test.mjs` (6th attempt 429; lockout after 10 failures refuses the correct password), `integration/rate-limit.test.mjs` (atomic upsert under 20 concurrent hits) |
| Session theft / fixation | HttpOnly + Secure cookies, rotation on login, server-side revocation, idle + absolute expiry | `unit/session.test.mjs` (tamper, expiry, rotation, revoke, cookie flags), `integration/admin-auth.test.mjs` (rotation, logout, 61-minute idle), `integration/threats.test.mjs` (attacker-chosen cookie values never authenticate) |
| User enumeration | Identical 401 body and status for unknown user and wrong password; verification always runs | `integration/admin-auth.test.mjs` (byte-identical bodies; missing configured hash → same body) |
| Visitor-list scraping | All reads behind the admin session; no public listing; no visitor data in static output | `integration/admin-queries.test.mjs` (401 unauthenticated), `integration/threats.test.mjs` (grep of `_site/` for seeded emails, secrets and server code), `integration/dev-app.test.mjs` (gate: pages → welcome, assets/PDF → 403) |
| CSV formula injection | Cells starting with `= + - @ TAB CR` prefixed with `'`; every cell quoted | `unit/csv-core.test.mjs`, `integration/export.test.mjs` (`=HYPERLINK(...)` neutralised after a real CSV parse) |
| Mass assignment | Explicit field allow-list in the validator; internal columns never taken from input | `unit/validate-registration.test.mjs` (`role: admin` dropped), `integration/threats.test.mjs` (`visit_count`, `privacy_version`, `id`, `created_at`, `is_admin` in the body do not reach the row) |
| Open redirect | Fixed post-register (`/`) and post-error (`/welcome/?error=`) destinations; login never redirects | `integration/threats.test.mjs` (`?next=` / `redirect=` ignored on register and login) |
| Secret leakage | `.env*` git-ignored; `npm run check:secrets` over tracked files and `_site/`; no bodies/cookies in logs | `unit/check-secrets-core.test.mjs`, `integration/threats.test.mjs` (`check:secrets` passes, `.env.local` untracked, no secrets in `_site/`), `integration/dev-app.test.mjs` (access log has no emails/cookies/bodies), `integration/export.test.mjs` (audit line has no data) |
| Direct asset access without registration | Middleware matcher covers normalized assets, `/print/`, `/content/`; per-item pages no longer built | `unit/gate.test.mjs` (decisions + Vercel protocol), `integration/dev-app.test.mjs` (403 on ad image/PDF without cookie, 200 with), `scripts/test-site.mjs` (no `_site/content` pages) |
| Dependency vulnerabilities | `npm audit` gate in the release pipeline; new application dependencies audit clean | **Manual, 2026-09-14:** `npm audit` after Task 18 — 4 pre-existing high findings in build tooling (`js-yaml` transitive, `playwright`, `sharp`, `xlsx`), 0 new; automated gate lands in Task 36 (Stream C) |
| Honeypot / automated abuse | Hidden field, minimum fill time, per-IP register limit | `integration/register.test.mjs` (honeypot silent 200 with no write; sub-2 s → 422; 6th per-IP → 429), `e2e/welcome-page.test.mjs` (field off-screen and aria-hidden) |
| Body size / malformed input | 8 KB cap, JSON shape checks, 415 for other types | `integration/rate-limit.test.mjs` (`readJsonBody`), `integration/register.test.mjs` (413/400) |
| Fail-closed configuration | Missing `SESSION_SECRET` → gate rewrites; missing admin hash → 401 | `unit/gate.test.mjs`, `integration/admin-auth.test.mjs` |

Not automated (documented for `/walkthrough` and deployment): HTTPS/HSTS and `Secure` cookies are enforced by `NODE_ENV=production` on Vercel (header set in `lib/http.ts`); Vercel's built-in DDoS mitigation; database least-privilege role and backups (DEPLOYMENT.md, Task 34).
